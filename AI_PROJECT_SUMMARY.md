# Tech Diagnosis AI - Project Summary

## Overview
This project is a multi-layer Knowledge-Based Expert System (KBS) built in Python for diagnosing computer hardware and software issues. It utilizes a custom Forward-Chaining Inference Engine with Confidence Factors (CF) and provides transparent reasoning through an Explanation Graph.

## Architecture & Core Components

### 1. `engine/inference_engine.py` (Forward Chaining Engine)
The core symbolic AI engine of the project.
- **Algorithm**: Implements multi-step forward chaining. It iterates over a loaded set of rules until no new facts are deduced or a maximum iteration limit is reached.
- **Conflict Resolution & Confidence**: Combines confidence factors (CF) from multiple rule firings. It tracks rule `specificity` (number of conditions) and `priority` to rank inferences.
- **Loop Protection**: Maintains a `fired_rules` set (storing signatures of `(rule_id, matched_facts)`) to prevent infinite reasoning loops.
- **Outputs**: Returns the updated working `memory` and a `trace_graph` (a record of all fired rules and their contributing facts).

### 2. `engine/explanation.py` (Explanation System)
Provides "Explainable AI" (XAI) capabilities for the expert system.
- **Algorithm**: Performs a backward traversal recursively on the `trace_graph` starting from a target conclusion.
- **Output**: Generates a human-readable tree string that traces exactly why a specific recommendation or root cause was inferred, linking it all the way back to the initial user inputs.

### 3. `engine/confidence.py`
Handles certainty factors.
- **Propagation**: Calculates the confidence of a conclusion based on the rule's inherent CF and the minimum CF of the triggering conditions.
- **Combination**: Combines confidence factors when multiple independent rules arrive at the same conclusion using standard MYCIN-like CF combination math (`CF1 + CF2 - (CF1 * CF2)`).

### 4. `ui/app.py` (Tkinter UI)
A modern, dark-themed responsive desktop GUI.
- **Layout**: Uses a strict 3-column Tkinter `.grid()` layout:
  1. **Left Panel (Symptoms)**: A scrollable `Canvas` generating `ttk.Checkbutton` widgets dynamically from `facts.json`.
  2. **Center Panel (Results)**: Displays the categorized inferences (`RECOMMENDED ACTIONS`, `ROOT CAUSES`, `DETECTED ISSUES`) sorted by CF and specificity.
  3. **Right Panel (Explanation)**: Renders the reasoning trace generated by the `ExplanationSystem`.
- **Threading**: The inference engine is triggered on a background `threading.Thread` so that the Tkinter main loop is not blocked during reasoning.

### 5. Knowledge Base (`knowledge_base/`)
- **`facts.json`**: Contains the raw user-selectable symptoms (e.g., "high disk usage", "overheating").
- **`rules.json`**: Contains the logical implications. Rules have `conditions` (required facts), a `conclusion`, a `confidence` weight, and a `layer` (indicating if the conclusion is an 'issue', 'cause', or 'recommendation').

### 6. `main.py`
The entry point of the application which initializes the UI and loads the knowledge base.

## Data Structures
- **Memory (`dict`)**: The working memory during inference. Format: `fact_id: {'value': bool, 'cf': float, 'name': str, 'layer': str, 'specificity': int, 'priority': int, 'is_inferred': bool}`.
- **Trace Graph (`list` of `dict`)**: Records inference edges. Format: `{'rule_id': str, 'from_facts': list, 'to_fact': str, 'layer': str, 'cf_contribution': float, 'rule_name': str}`.

## Tech Stack & Dependencies
- **Language**: Python 3
- **GUI**: Tkinter (Standard Library)
- **Data Format**: JSON
- **Paradigm**: Symbolic AI / Rule-Based System (No machine learning models like PyTorch/TensorFlow are used).
